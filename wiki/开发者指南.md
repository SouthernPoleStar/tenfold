# 开发者指南

给想改数值、加内容或自己构建的人。

## 构建

```bash
# JDK 17
./gradlew build            # 产物 build/libs/tenfold-0.1.14.jar
./gradlew runClient        # 开发客户端
./gradlew runServer        # 开发服务端
```

Windows 下如果没配 `JAVA_HOME`，先指到 JDK 17 再跑 `gradlew.bat build --console=plain`。

版本号、模组名等都在 `gradle.properties`：

```properties
mod_id=tenfold
mod_version=0.1.14
forge_version=47.2.0
minecraft_version=1.20.1
```

## 几个坑（都踩过）

1. **`generic.max_health` 上限是 1024**：`RangedAttribute("generic.max_health", 20, 1, 1024)` 把上限写死了，8000 血会被 clamp。`AttributeLimits` 用反射改字段，必须在 `commonSetup` 里执行。
2. **`LivingHurtEvent` 是护甲前，`LivingDamageEvent` 是护甲后**：想做"终值封顶"（比如毅力 3 点）必须挂在 `LivingDamageEvent`。
3. **`Mob` 没有 `setOrderedToSit`**：Poey 自己存了一个 `sitting` 字段，别照抄 Wolf 的写法。
4. **护甲贴图路径**：`HumanoidArmorLayer.getArmorResource` 会把材质名按 `:` 切开，Forge 路径下 `"tenfold:gear"` 会解析成 `tenfold:textures/models/armor/gear_layer_1.png`。要完全自定义就重写 `IForgeItem#getArmorTexture` 返回完整路径——透明护甲层就是这么做的。
5. **命中判定范围**：射线检测用 `±RANGE` 而不是 `±RANGE/2`，否则远处目标打不中。
6. **契约计时要在所有槽位生效**：只看主手会漏掉背包/副手，导致高亮常驻、违约不判。

## 发布

1. `gradle.properties` 改 `mod_version`。
2. 更新 `README.md` 与 `CHANGELOG.md`。
3. `./gradlew build`，取 `build/libs/tenfold-<版本>.jar`。
4. 提交源码（**不要把 `build/` 或 jar 提交进仓库**，`.gitignore` 已经排除）。

> 仓库不放 GitHub Actions 工作流：每次 push 都触发完整 Gradle 构建属于 Actions 滥用，也容易踩到平台风控。
